# Quickstart: 002 부부 가입·연결 온보딩 검증

구현이 끝났을 때 기능이 처음부터 끝까지 동작하는지 확인하는 절차다. 계약은 `contracts/`, 데이터는
`data-model.md`를 참조한다.

## 0. 준비

- 001 준비(`specs/001-quant-mind-dashboard/quickstart.md` §0)를 마친 상태
- 002 마이그레이션 적용: `npx supabase db push --linked` (적용 전 `--dry-run`으로 확인)
- `pg_cron` 확장이 켜져 있고 `process_due_departures`가 1시간마다 실행되도록 등록되어 있음
- 테스트용 이메일 두 개(A, B). **실제 운영자 계정이 아닌 계정**을 쓴다
- 두 계정의 `user_profile.is_internal = true`로 설정(분석 집계에서 제외)

## 1. 자동 검증

```bash
npm run lint && npm test && npm run build
npm run test:e2e            # mock 모드, 데스크톱·모바일
npm run test:integration    # QM_IT_* 환경변수가 있을 때만 실행됨
```

기대 결과: 모두 통과. 통합 테스트가 확인하는 것은 다음과 같다.
- 공개 동의 전에는 상대 금액이 응답에 없음(SC-003)
- 정원 2명 초과 불가(SC-006)
- 탈퇴 기간 중 작성 차단
- anon 요청 거부

## 2. 수동 시나리오 (supabase 모드, 창 두 개)

| 번호 | 할 일 | 기대 결과 | 근거 |
|---|---|---|---|
| 2-1 | A 가입 → 인증 메일 확인 → 약관 동의 → household 생성 | 빈 대시보드와 배우자 초대 안내가 보임. 인증 대기를 빼고 5분 이내 | US1, SC-001 |
| 2-2 | A가 약관 동의 없이 다음으로 진행 시도 | 진행 안 됨, 동의 안내 | FR-002 |
| 2-3 | A가 초대 링크 만들기 | 링크와 만료 시각(7일 뒤) 표시 | FR-006 |
| 2-4 | B(시크릿 창)가 링크로 가입·동의·수락 | 같은 household 합류. 인증 대기를 빼고 5분 이내 | US2, SC-002 |
| 2-5 | 같은 링크를 다시 수락 시도 | "쓸 수 없는 초대" 안내 | FR-008 |
| 2-6 | A가 표준 양식을 내려받아 2행 작성 후 업로드 | 대시보드에 A 자산 표시, 기준 시점이 업로드 시각 | US3, FR-011 |
| 2-7 | 평가금액 칸에 글자를 넣고 업로드 | 아무것도 바뀌지 않고 행·열·이유 표시 | FR-011 |
| 2-8 | B 화면 확인(A 공개 동의 전) | "상대방이 아직 공개하지 않음". 네트워크 응답에 A 금액 필드 없음 | FR-012, SC-003 |
| 2-9 | A가 공개 동의 → B 화면 | A 자산이 보임 | FR-012 |
| 2-10 | B도 업로드·공개 동의 → A가 대시보드 열기 | 부부 합계 표시, `activation_record.first_valid_view_at` 기록 | Activation 정의 |
| 2-11 | A가 내 자산 내보내기 → 그 파일을 그대로 업로드 | 같은 계좌·종목 복원 | SC-011 |
| 2-12 | A가 탈퇴 요청 | 삭제 대상·예정 시각 안내 후 확인. B에게 탈퇴 예정 안내 | FR-014a, FR-014d, FR-016 |
| 2-13 | 기간 중 A가 안건 작성 시도 | 막힘 | FR-014a |
| 2-14 | B가 판단 로그 내보내기 | A가 쓴 안건·의견 포함된 파일 | FR-014c |
| 2-15 | A가 탈퇴 취소 | 아무것도 지워지지 않음 | US4-5 |
| 2-16 | 다시 탈퇴 요청 후 SQL로 `scheduled_at`을 과거로 바꾸고 `select process_due_departures();` | A 자산·작성 기록 삭제. A가 확정한 B 안건의 합의는 "떠난 구성원"으로 남음 | FR-014, SC-010 |
