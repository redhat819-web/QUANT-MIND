# Feature Specification: QUANT-MIND 공동 자산 관리 대시보드

**Feature Branch**: `001-quant-mind-dashboard`

**Created**: 2026-09-05

**Status**: Draft

**Input**: User description: "QUANT-MIND라는 부부 공동 자산 관리 대시보드를 만들고 싶다. 두 사람이 각자 흩어져 있는 계좌 자산을 하나의 화면에서 합쳐 보고, 성장/방어/현금 비중을 확인하고, 투자 안건에 의견을 남기고 합의를 기록하는 도구."

## Clarifications

### Session 2026-09-05

- Q: 안건이 "논의중" 상태인 동안, 작성자 본인만 제목/내용을 수정할 수 있어야 하는가, 아니면 상대 운영자도 함께 수정할 수 있어야 하는가? → A: 작성자만 제목/내용 수정 가능 (상대방은 의견으로만 반응)
- Q: 대시보드의 자산 집계 구조와 수익률 계산 방식은 어떠해야 하는가? → A: 계좌 단위 → 개인 통합(운영자별 다수 계좌 합산) → 부부 통합(두 개인 통합의 합산)의 3단계 구조로 표시하며, 개인 통합과 부부 통합 모두 "전체 평가금액 기준 가중 평균" 방식으로 수익률을 계산한다.
- Q: 안건에 아직 아무 의견도 달리지 않은 상태(의견 0건)에서도 합의 확정이 허용되어야 하는가? → A: 의견 0건 상태에서도 합의 확정을 허용한다.
- Q: 두 스프레드시트의 종목 표기가 달라 매핑 정의로 자동 매칭되지 않는 경우 시스템은 이를 어떻게 처리해야 하는가? → A: 매핑 실패 종목은 목록에서 제외하지 않고 "미매핑" 상태로 그대로 표시하며, 운영자가 화면에서 수동으로 매핑을 등록할 수 있게 한다.

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 통합 자산 현황과 비중 확인 (Priority: P1)

운영자는 로그인 후 대시보드에서 세 단계로 집계된 자산 현황을 확인할 수 있다:
(1) 자신의 여러 계좌를 합산한 "개인 통합" 총 평가금액과 개인 수익률, (2) 상대
운영자의 "개인 통합" 총 평가금액과 개인 수익률, (3) 두 사람의 개인 통합을 다시
합산한 "부부 통합" 총 평가금액과 부부 통합 수익률. 또한 성장/방어/현금 세 가지
분류의 비중, 현재 논의 중인 안건 요약, "참고용 — 투자 권유 아님" 안내 문구를
함께 본다.

**Why this priority**: 이 기능이 없으면 프로젝트의 핵심 동기(흩어진 자산을 한눈에
합쳐 보는 것)가 성립하지 않는다. 개인 통합 단계가 빠지면 "누구의 자산이 얼마인지"를
알 수 없어 부부 통합 숫자만으로는 논의의 근거가 부족해진다. 다른 모든 화면은 이
통합 뷰를 보완하는 역할이다.

**Independent Test**: 두 운영자 계정에 각각 계좌/종목 데이터가 등록된 상태에서
한 운영자로 로그인해 대시보드에 접속하면, 나의 개인 통합, 상대방의 개인 통합,
부부 통합 총액·수익률·비중이 표시되고 별도의 다른 화면 없이도 이 자체로 가치를
확인할 수 있다.

**Acceptance Scenarios**:

1. **Given** 두 운영자 각각 유효한 계좌·종목 데이터가 존재하는 상태, **When** 운영자가
   로그인하여 대시보드에 접속하면, **Then** 로그인한 운영자 본인의 개인 통합
   총 평가금액과 개인 수익률이 표시된다.
2. **Given** 두 운영자 각각 유효한 계좌·종목 데이터가 존재하는 상태, **When** 대시보드를
   조회하면, **Then** 상대 운영자의 개인 통합 총 평가금액과 개인 수익률도 함께
   표시된다.
3. **Given** 두 운영자의 개인 통합 값이 모두 계산된 상태, **When** 대시보드를
   조회하면, **Then** 두 사람의 개인 통합을 다시 합산한 부부 통합 총 평가금액과
   부부 통합 수익률이 "나: OOO원 (+O%)", "상대방: OOO원 (+O%)", "부부 합계:
   OOO원 (+O%)" 형태로 세 값이 함께 표시된다.
4. **Given** 대시보드가 로드된 상태, **When** 종목 분류가 성장/방어/현금으로 지정되어
   있으면, **Then** 각 분류가 차지하는 비중이 세 항목 모두에 대해 표시된다.
5. **Given** 논의 중(합의 미확정) 안건이 하나 이상 존재하는 상태, **When** 대시보드를
   조회하면, **Then** 해당 안건들의 요약(제목, 상태)이 목록으로 표시된다.
6. **Given** 임의의 대시보드 조회 시점, **When** 화면이 렌더링되면, **Then** "참고용 —
   투자 권유 아님" 문구가 항상 함께 표시된다.
7. **Given** 로그인하지 않은 사용자, **When** 대시보드 접근을 시도하면, **Then** 로그인
   안내 화면으로 이동하고 실제 자산 데이터는 전혀 전달되지 않는다.
8. **Given** 자산 데이터가 마지막으로 반영된 시점이 존재하는 상태, **When** 대시보드를
   조회하면, **Then** 화면 최상단에 "기준 시점: YYYY-MM-DD HH:mm 기준"이 항상
   표시된다.

### User Story 2 - 계좌·종목 상세 조회와 분류 수정 (Priority: P2)

운영자는 계좌별 요약과 종목별 상세(보유 수량, 평가금액, 손익률, 분류)를 빠른 확인
모드와 상세 모드로 조회하고, 필요 시 특정 종목의 분류(성장/방어/현금)를 수동으로
변경할 수 있다.

**Why this priority**: 대시보드의 합산 수치가 어디서 왔는지 근거를 확인하고 분류
오류를 바로잡을 수 있어야 대시보드의 신뢰도가 유지된다. P1이 있어야 의미가 커지므로
그다음 우선순위다.

**Independent Test**: 계좌·종목 데이터가 존재하는 상태에서 이 화면에 단독으로
접근해, 계좌별 요약 확인 → 특정 종목 상세 확인 → 분류 변경까지 완결된 흐름으로
검증 가능하다.

**Acceptance Scenarios**:

1. **Given** 운영자가 계좌·종목 리스트 화면에 접속한 상태, **When** 빠른 확인 모드를
   선택하면, **Then** 계좌별 요약(계좌명, 합계 평가금액, 대표 손익률)이 표시된다.
2. **Given** 빠른 확인 모드가 표시된 상태, **When** 특정 계좌 또는 종목의 상세 모드를
   선택하면, **Then** 종목명, 보유 수량, 평가금액, 손익률, 분류 및 존재하는 조건부
   항목(종목코드, 통화, 평균 매입가, 배당)이 표시된다.
3. **Given** 상세 모드에서 종목을 보고 있는 상태, **When** 운영자가 분류를 다른 값
   (성장/방어/현금)으로 변경하고 저장하면, **Then** 변경된 분류가 즉시 반영되고
   대시보드의 비중 계산에도 반영된다.
4. **Given** 어떤 종목에 조건부 항목(예: 배당) 값이 없는 상태, **When** 해당 종목의
   상세를 조회하면, **Then** 화면은 오류 없이 정상적으로 표시되고 해당 항목은
   "데이터 없음"으로 표기된다.
5. **Given** 다른 운영자가 등록한 계좌, **When** 로그인한 운영자가 이를 조회하면,
   **Then** 자신의 계좌와 동일한 방식으로 상대방의 계좌·종목도 조회할 수 있다.

### User Story 3 - 투자 안건 작성과 합의 기록 (Priority: P3)

운영자는 투자 안건을 작성하고, 상대 운영자는 해당 안건에 의견을 남기며, 두
운영자가 논의 후 합의를 확정할 수 있다. 확정된 합의는 이후에도 다시 조회할 수
있다.

**Why this priority**: 판단 로그는 자산 조회(P1, P2) 위에서 이루어지는 논의
활동으로, 데이터 조회 기능이 먼저 안정화된 뒤에 의미가 생기는 상호작용 계층이다.

**Independent Test**: 계좌 데이터 유무와 무관하게, 안건 작성 → 상대방 의견 등록 →
합의 확정 → 확정 목록에서 재조회까지의 흐름만으로 독립적으로 검증 가능하다.

**Acceptance Scenarios**:

1. **Given** 로그인한 운영자, **When** 제목(1~100자)과 내용(1~2000자)을 입력해 안건을
   작성하면, **Then** 안건이 "논의중" 상태로 생성되고 작성자·작성 시각이 함께
   기록된다.
2. **Given** "논의중" 상태의 안건이 존재하는 상태, **When** 상대 운영자가 의견
   (1~2000자)을 남기면, **Then** 의견이 작성자·작성 시각과 함께 안건에 추가된다.
3. **Given** "논의중" 상태의 안건(의견이 0건이어도 무방), **When** 두 운영자 중 한 명이 합의
   확정을 실행하면, **Then** 안건 상태가 "합의완료"로 변경되고 확정 시각과 확정
   수행자가 기록된다.
4. **Given** "합의완료" 상태의 안건, **When** 운영자가 판단 로그 목록에서 이를
   조회하면, **Then** 안건 내용, 전체 의견 이력, 합의 확정 정보가 그대로 재조회된다.
5. **Given** 이미 "합의완료" 처리된 안건, **When** 운영자가 해당 기록을 수정하려고
   시도하면, **Then** 원본을 덮어쓰지 않고 변경 이력(이전 값, 수정자, 수정 시각,
   사유)이 남는 방식으로만 수정이 반영된다.
6. **Given** 제목이 공백만으로 구성되거나 100자를 초과, 또는 내용/의견이 공백만이거나
   2000자를 초과하는 입력, **When** 저장을 시도하면, **Then** 저장이 거부되고 입력
   규칙 위반 사유가 표시된다.

---

### Edge Cases

- 조건부 표시 항목(종목코드, 통화, 평균 매입가, 배당)이 전혀 없는 종목을 조회하면
  어떻게 되는가? → 해당 항목은 "데이터 없음" 상태로 표시되고 화면·계산 로직은
  정상 동작해야 한다.
- 두 스프레드시트에서 같은 종목이 서로 다르게 표기되어 매핑 정의로 자동 매칭되지
  않는 경우 → 해당 종목은 계좌·종목 리스트에서 제외되지 않고 "미매핑" 상태로
  그대로 표시되며, 운영자가 화면에서 수동으로 매핑을 등록할 수 있어야 한다.
- 계좌·종목 데이터가 전혀 없는 상태에서 대시보드에 접속하면 → 빈 목록/데이터 없음
  상태로 표시되며 오류가 발생하지 않는다.
- 로그인하지 않은 사용자가 계좌·종목 리스트나 판단 로그 등 보호된 화면에 직접
  접근하면 → 로그인 안내로 이동하며 데이터는 전혀 전달되지 않는다.
- 안건에 아직 의견이 하나도 없는 상태에서 합의 확정을 시도하면 → 시스템은 논의
  없이 합의가 확정되었음을 알 수 있는 방식으로 처리한다(합의 확정 자체는 허용하되
  의견 0건 상태가 기록에 남는다).
- 네트워크 오류나 서버 오류로 데이터 조회/저장에 실패하면 → 오류 상태를 표시하고
  재시도가 가능해야 한다.
- 권한이 없는 사용자가 자산 데이터 요청을 직접 시도하면(예: 화면을 거치지 않고) →
  "권한 없음" 상태로 응답하고 금액 데이터는 포함되지 않는다.
- 스프레드시트 원본 형식이 예상 매핑 규칙과 맞지 않는 열을 포함하면 → 시스템은
  해당 데이터를 오류로 표시하고 원본 스프레드시트 형식 자체는 변경을 요구하지
  않는다.

## Requirements *(mandatory)*

### Functional Requirements

**인증 및 권한**

- **FR-001**: 시스템은 운영자가 로그인/로그아웃할 수 있는 기능을 제공해야 한다.
- **FR-002**: 시스템은 인증되지 않은 사용자가 보호된 화면(대시보드, 계좌·종목 리스트,
  판단 로그)에 접근할 때 로그인 안내를 표시하고, 실제 금액을 포함한 데이터는
  어떤 경로로도 반환하지 않아야 한다.
- **FR-003**: 시스템은 두 운영자가 서로의 자산, 계좌·종목, 안건, 의견을 동일한
  권한으로 조회하고 상호작용(의견 작성, 합의 확정)할 수 있도록 해야 하며, 한
  운영자에게만 허용되는 승인·차단 권한을 두어서는 안 된다.
- **FR-004**: 시스템은 공개 열람자에게 실제 계좌 금액, 평가금액, 손익 금액을 어떤
  형태로도 노출하지 않아야 한다(공개 화면 자체의 구현은 본 기능의 범위에서
  제외되며, 이 요구사항은 향후 공개 화면 구현 시 데이터 계약으로 적용된다).

**통합 자산 현황 (대시보드)**

- **FR-005**: 시스템은 세 단계로 자산을 집계하여 대시보드에 표시해야 한다:
  (a) 개인 통합 — 각 운영자의 여러 계좌를 합산한 개인 총 평가금액과 개인 수익률
  (본인 및 상대방 모두), (b) 부부 통합 — 두 운영자의 개인 통합을 다시 합산한
  부부 전체 총 평가금액과 부부 통합 수익률. 개인 통합과 부부 통합은 동시에 함께
  표시되어야 하며, 부부 통합만 표시하고 개인 통합을 생략해서는 안 된다.
- **FR-005a**: 개인 수익률과 부부 통합 수익률은 모두 해당 범위(개인 또는 부부
  전체)의 전체 평가금액을 기준으로 한 가중 평균 방식으로 계산해야 하며, 계좌
  또는 개인 수익률을 단순 평균하는 방식을 사용해서는 안 된다.
- **FR-006**: 시스템은 보유 종목의 분류(성장/방어/현금)별 비중을 계산하여 표시해야
  한다.
- **FR-007**: 시스템은 대시보드에 현재 "논의중" 상태인 안건의 요약 목록(제목, 상태)을
  표시해야 한다.
- **FR-008**: 시스템은 분석 결과가 표시되는 모든 화면(대시보드 포함)에 "참고용 —
  투자 권유 아님" 문구를 표시해야 한다.

**계좌·종목 리스트**

- **FR-009**: 시스템은 계좌별 요약(계좌명, 합계 평가금액, 대표 손익률)을 조회할 수
  있는 빠른 확인 모드를 제공해야 한다.
- **FR-010**: 시스템은 종목별 상세 정보(보유 수량, 평가금액, 손익률, 분류 및 조건부
  항목)를 조회할 수 있는 상세 모드를 제공해야 한다.
- **FR-011**: 시스템은 운영자가 종목의 분류(성장/방어/현금)를 수동으로 변경할 수
  있도록 해야 하며, 변경 시 대시보드의 비중 계산에도 즉시 반영되어야 한다.
- **FR-012**: 시스템은 필수 데이터 항목(소유자, 계좌, 종목명, 수량, 평가금액(원화),
  손익률, 분류)을 모든 종목에 대해 표시해야 한다.
- **FR-013**: 시스템은 조건부 데이터 항목(종목코드, 통화, 평균 매입가, 배당)이 값이
  없는 경우에도 화면이 정상적으로 성립하도록 해야 하며, 값이 없는 항목은
  "데이터 없음" 상태로 표시해야 한다.

**데이터 통합 및 매핑**

- **FR-014**: 시스템은 두 운영자가 각각 관리하는 서로 다른 형식의 스프레드시트
  데이터를, 원본 형식을 변경하지 않고 표준 내부 형태로 변환하여 사용해야 한다.
- **FR-015**: 시스템은 서로 다른 표기로 등록된 동일 종목을 매핑 정의를 통해
  하나의 표준 종목으로 인식할 수 있어야 한다. 매핑 정의로 자동 매칭되지 않는
  항목은 목록에서 제외하지 않고 "미매핑" 상태로 그대로 노출해야 하며, 운영자가
  화면에서 수동으로 매핑을 등록할 수 있어야 한다.

**판단 로그 (안건/의견/합의)**

- **FR-016**: 시스템은 운영자가 투자 안건을 작성할 수 있도록 해야 하며, 제목은
  공백 제거 후 1~100자, 내용은 공백 제거 후 1~2000자 범위를 벗어나면 저장을
  거부해야 한다.
- **FR-016a**: 시스템은 "논의중" 상태의 안건에 대해 작성자 본인만 제목/내용을
  수정할 수 있도록 해야 하며, 상대 운영자는 해당 안건에 의견(Opinion)을 남기는
  방식으로만 대응할 수 있다.
- **FR-017**: 시스템은 운영자가 기존 안건에 의견을 작성할 수 있도록 해야 하며,
  의견은 공백 제거 후 1~2000자 범위를 벗어나면 저장을 거부해야 한다.
- **FR-018**: 시스템은 안건 상태를 "논의중"과 "합의완료"로 구분하여 표시해야 한다.
- **FR-019**: 시스템은 운영자가 안건에 대해 합의를 확정할 수 있도록 해야 하며,
  확정 시 상태가 "합의완료"로 변경되고 확정 수행자와 확정 시각이 기록되어야
  한다. 의견이 0건인 안건도 합의 확정이 허용되어야 하며, 의견 개수를 합의 확정의
  전제 조건으로 강제해서는 안 된다.
- **FR-020**: 시스템은 합의 확정된 안건을 이후에도 조회할 수 있도록 유지해야
  한다.
- **FR-021**: 시스템은 합의 확정된 기록이 수정될 경우 원본을 덮어쓰지 않고 변경
  이력(이전 값, 수정자, 수정 시각, 사유)을 남겨야 한다.
- **FR-022**: 시스템은 모든 안건과 의견 기록에 작성자와 작성 시각을 함께 저장하고
  표시해야 한다.

**상태 처리**

- **FR-023**: 시스템은 데이터 조회 중 로딩, 목록이 비어 있는 빈 목록, 오류, 권한
  없음, 저장 중, 조건부 항목이 없는 데이터 없음 상태를 화면에 명확히 구분하여
  표시해야 한다.
- **FR-024**: 시스템은 대시보드 화면 최상단에 자산 데이터가 마지막으로 반영된
  시점을 "기준 시점: YYYY-MM-DD HH:mm 기준" 형태로 항상 표시해야 한다. 이 표시는
  정기 자동 갱신 주기와 무관하게, 자동 갱신이든 운영자의 수동 동기화든 실제로
  반영된 가장 최근 시점을 그대로 나타내야 한다.

### Key Entities *(include if feature involves data)*

- **운영자(Operator)**: 로그인 가능한 사용자로, 두 명이 존재하며 서로 동등한 권한을
  가진다. 자신 및 상대방의 계좌, 종목, 안건, 의견에 접근할 수 있다.
- **계좌(Account)**: 특정 운영자(소유자)에게 속하며, 하나 이상의 종목(보유 자산)을
  포함한다. 계좌별 합계 평가금액과 대표 손익률을 가진다.
- **종목/보유자산(Holding)**: 계좌에 속한 개별 보유 항목. 필수 항목(소유자, 계좌,
  종목명, 수량, 평가금액, 손익률, 분류)과 조건부 항목(종목코드, 통화, 평균 매입가,
  배당)을 가진다. 분류는 성장/방어/현금 중 하나이며 운영자가 수동으로 변경 가능하다.
- **매핑 정의(Mapping Rule)**: 각 운영자의 원본 스프레드시트 열 구성/표기를 표준
  내부 항목과 종목 식별자로 변환하는 규칙. 동일 종목의 서로 다른 표기를 하나로
  묶는 데 사용된다.
- **안건(Agenda)**: 투자 논의 주제. 제목, 내용, 작성자, 작성 시각, 상태(논의중/
  합의완료)를 가진다.
- **의견(Opinion)**: 특정 안건에 달리는 코멘트. 내용, 작성자, 작성 시각을 가진다.
- **합의 기록(Agreement Record)**: 안건이 합의완료로 전환될 때 생성되는 확정 정보
  (확정 수행자, 확정 시각)와, 이후 수정 시 남는 변경 이력(이전 값, 수정자, 수정
  시각, 사유)을 포함한다.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 로그인한 운영자는 별도 화면 이동 없이 대시보드 진입 5초 이내에
  본인의 개인 통합 총액·수익률, 상대방의 개인 통합 총액·수익률, 부부 통합
  총액·수익률, 그리고 성장/방어/현금 비중을 모두 확인할 수 있다.
- **SC-002**: 운영자는 계좌·종목 리스트에서 특정 종목을 3회 이하의 조작(빠른 확인
  모드 진입 → 상세 모드 선택 → 분류 변경)으로 분류를 변경할 수 있다.
- **SC-003**: 조건부 데이터 항목이 없는 종목이 전체의 100%인 극단적 상황에서도
  화면 오류나 빈 화면 없이 모든 필수 항목이 정상 표시된다.
- **SC-004**: 안건 작성부터 상대방 의견 등록, 합의 확정까지의 전체 흐름을 5분
  이내에 완료할 수 있다.
- **SC-005**: 합의 확정된 안건의 100%는 확정 이후 언제든 원문과 의견 이력을 그대로
  재조회할 수 있다.
- **SC-006**: 서로 다른 형식의 두 스프레드시트에서 가져온 자산 데이터가 매핑 정의
  적용 후 통합 대시보드에서 단일 통화·단일 표준 형태로 100% 일치되게 표시된다.
- **SC-007**: 로그인하지 않은 사용자가 보호된 화면에 접근한 100%의 경우에서 실제
  금액 데이터가 응답에 포함되지 않는다.
- **SC-008**: 운영자 두 명 중 누구든 동일한 절차로 상대방의 자산·안건에 접근하고
  상호작용할 수 있어, 권한 비대칭으로 인한 작업 실패 사례가 0건이다.
- **SC-009**: 대시보드를 조회하는 100%의 경우에서 화면 최상단에 "기준 시점"이
  표시되며, 이 시점은 실제로 데이터가 마지막 반영된 시각과 항상 일치한다.

## Assumptions

- 안건(Agenda)은 특정 종목이나 계좌에 강제로 연결되지 않는 자유 주제이며, 자산
  데이터와는 독립적으로 생성·조회된다(연결 기능은 본 범위에 없음).
- "합의완료" 이후의 수정만 변경 이력 보존 대상으로 간주한다(FR-016a 및
  FR-021 참조).
- 종목 단위 손익률은 (평가금액 - 매입원가) 기준으로 계산한다는 표준 방식을
  가정한다(개인/부부 통합 수익률의 계산 방식은 FR-005a에서 확정됨).
- 스프레드시트 데이터는 자동(하루 1회, 저녁 시간대) 동기화와 운영자의 수동
  동기화를 함께 지원하는 방식으로 반영된다(구체 주기·시간대는 계획 단계에서
  확정, plan.md/research.md 참조). FR-024의 "기준 시점" 표시는 이 갱신 주기와
  무관하게 항상 정확한 마지막 반영 시각을 보여줘야 한다.
- 공개 열람자용 화면은 이번 기능의 구현 범위에서 제외되지만, 데이터 계약(금액
  비노출)은 이번 스펙에서 확정하여 이후 구현 시 그대로 적용한다.
- 통화는 기본적으로 원화(KRW)를 기준으로 하며, 조건부 항목인 "통화"는 원화가
  아닌 외화 보유 종목에 한해 표시된다.
- 세 핵심 화면(대시보드, 계좌·종목 리스트, 판단 로그)은 데스크톱과 모바일 환경
  모두에서 핵심 시나리오를 완결할 수 있어야 한다(프로젝트 헌장 원칙 XV).
