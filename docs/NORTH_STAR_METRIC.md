## 1. 후보 비교

공통: 행동 주체는 household의 두 구성원 중 누구든, 단위는 고유 household 수, 기간은 롤링 28일
(KST 기준 주별 기록).

| 후보 | 정확한 정의 | 고객 가치 | 왜곡 위험 | 측정 상태 |
|---|---|---|---|---|
| **A. 공동 자산 확인 household** | 최근 28일 동안 Activation 조건 ①~⑤를 만족하는 대시보드를 1회 이상 본 household 수. 품질 조건: 조회 시점에 두 구성원의 데이터가 모두 30일 이내 반영. 제외: 내부·테스트 계정, mock 모드 | 흩어진 두 사람의 자산을 한 화면에서 합쳐 보는 것(핵심 Job) | 낮음~중간. household당 1회로 세므로 반복 조회로 늘지 않음. 품질 조건이 없으면 오래된 데이터 조회도 가치로 셈 | 미측정. 002 미구현, 마지막 유효 조회 시각 기록 없음 |
| **B. 공동 합의 household** (현재 앱에 있는 행동) | 최근 28일 동안 작성자가 아닌 구성원의 의견이 1건 이상 달린 안건에서 합의가 확정된 household 수. 제외: 의견 0건 합의, `[통합테스트]`·`[점검]` 안건, 내부 계정 | 함께 판단하고 그 결과를 기록으로 남기는 것 | 중간. 가벼운 안건으로 부풀릴 수 있음. 의견 조건으로 일부 막음 | 미측정. 현재 DB(`agreement_record`, `opinion`)로 계산할 수 있지만 household가 1개이고 코호트 대상이 아니라 계산하지 않음 |

| 기준 | A | B |
|---|---|---|
| 고객 가치와의 거리 | 핵심 가치를 직접 확인하지만 보는 행동임 | 판단 결과까지 이어져 가치에 더 가까움 |
| 반복 측정 | 자산 확인 주기(월 1회 이상)와 맞음 | 합의는 드묾. 28일 안에 0건인 건강한 household가 많을 수 있음 |
| 게임화 위험 | 업로드 재촉 알림으로 끌어올릴 수 있음 | 사소한 안건 생성 유도 |
| 누락 | 배우자 공개 미동의, 1인 household (의도된 누락) | 앱 밖(메신저·대면)에서 논의하는 household. `docs/USER_FLOW_ANALYSIS.md` §6의 미확인 사항 |
| 데이터 상태 | 002 구현과 조회 기록 필요 | 현재 스키마로 계산 가능 |

## 2. 우선 후보: A

- 두 사람의 합류, 데이터 업로드, 공개 동의가 모두 있어야 올라간다. 첫 가설("배우자도 합류하는가")과
  핵심 Job을 함께 반영한다.
- B는 빈도가 낮고 앱 밖에서 논의하는 부부를 0으로 센다. B는 보조 지표로 함께 본다.
- **Activation과 다르다.** Activation Rate는 새 household 코호트가 168시간 안에 첫 가치에 도달한
  **비율**이다. NSM은 전체 household 중 최근 28일 동안 가치를 받은 household의 **수**다.

### Input → NSM

| Input Metric | 정의 | NSM에 미치는 영향 |
|---|---|---|
| I1. 신규 활성 household 수 | 주별로 Activation 조건을 처음 달성한 household 수 | NSM 모수로 새로 들어옴 |
| I2. 데이터 최신 유지율 | 활성 household 중 두 구성원 모두 **보유 내역** 마지막 반영이 30일 이내인 비율 | 자동 갱신이 없어 이 비율이 떨어지면 품질 조건 때문에 NSM도 떨어짐 |

```
NSM(28일) ≈ 누적 활성 household × 데이터 최신 유지율(I2) × 그중 28일 안에 조회한 비율
              ↑ I1이 쌓여서 늘어남
```

## 3. Guardrail

| Guardrail | 정의 | 막으려는 것 |
|---|---|---|
| G1. 공개 철회·탈퇴 요청 비율 | 28일 동안 배우자 공개 동의를 철회했거나 탈퇴를 요청한 household 비율 | NSM을 위해 공개를 압박해 관계·개인정보 불편이 커지는 것 |
| G2. 업로드 실패 후 미복구 비율 | 검증 실패 업로드 중 7일 안에 성공 업로드가 없는 비율 | 업로드 재촉으로 I2를 올리는 동안 양식이 어려워 이탈이 늘어나는 것 |

지표와 별개로 금액 정보가 상대방에게 노출된 경우 0건(002 SC-003)은 넘을 수 없는 조건이다.

### 다시 검토할 조건

- 보유 내역 자동 갱신이 생겨 I2가 의미를 잃을 때(아래 4절상 당분간 없음)
- 인터뷰(`docs/ACTIVATION_DEFINITION.md` §5)에서 가치가 "본 것"보다 "함께 결정한 것"에서 나온다는 답이
  많을 때
- household 정원 규칙이 바뀔 때(1인, 3인 이상)
- G1·G2가 계속 오르는데 NSM만 오를 때

## 4. 자동 갱신 가능 범위 검토

자동 갱신은 **보유 내역**(계좌·종목·수량)과 **가격**(평가금액·수익률)으로 나눠 본다. 수동 업로드의
불편은 주로 매일 바뀌는 가격에서 생긴다.

| 방식 | 갱신 대상 | 판단 | 근거·장애물 |
|---|---|---|---|
| 마이데이터(본인신용정보관리업) | 보유 내역 + 가격 | 불가(범위 밖) | 금융위원회 허가 필요. 최소 자본금 5억원, 보안설비, 대주주·임원 적격성 등 심사 |
| 증권사 Open API(예: 한국투자증권 KIS) | 보유 내역 + 가격 | 불가 | 고객 대상 서비스 제휴는 투자일임·투자자문 제도권 금융회사만 가능, 핀테크사 불가라고 안내됨. 증권사 한 곳만 지원 |
| 스크래핑 중계 API | 보유 내역 + 가격 | 권장 안 함 | 금융 로그인 정보·인증서를 다뤄 보안 부담이 가장 큼. 제도상 허용 범위는 확인하지 못함(법률 검토 필요) |
| Google 시트 연결(`drive.file`) | 사용자가 시트에 적은 내용 | 가능, 효과 작음 | 심사 부담은 작지만 정기 읽기에 서버 작업·토큰 보관 필요("별도 백엔드 없음"과 충돌). 수량은 여전히 수동 |
| 가격만 서비스가 갱신(업로드 수량 × 매일 시세) | 가격 | 가능(조건부) | 공공데이터포털 금융위원회 주식시세정보가 후보. 상업 이용 허락 범위 미확인, 시세 이용에 KRX 정보이용계약이 필요할 수 있음. 해외 종목·환율 출처 별도 |

**결론**
- 002는 표준 양식 수동 업로드를 유지한다.
- 가격 자동 갱신은 후속 기능(003 후보)으로 둔다. 시작 전에 확인할 것:
  1. 시세 데이터 상업 이용 조건
  2. 해외 종목·환율 시세 출처
  3. 기준 시점을 "보유 내역 반영 시각"과 "가격 기준 시각"으로 나누는 것(001 FR-024 영향)
- 보유 내역 자동 갱신은 허가·제휴를 검토할 사업 단계 전까지 다루지 않는다.
- 법·약관 판단은 웹 검색으로 확인한 범위까지다. 출시 전 원문 확인과 전문가 검토가 필요하다.
